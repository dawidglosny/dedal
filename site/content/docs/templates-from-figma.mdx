**In short:** designers build the page in Figma from your design system's components; one command turns the frame into a Dedal template, checked against the contract; your components render it. Change the frame, pull again — the page follows, with no frontend release. Every layer that didn't make it into the template is reported with its Figma path.

## What's in the box

| | What it does | Page |
|---|---|---|
| **`dedal/figma`** | `mapping(contract, …)` — how Figma's components, properties and native slots become contract components, props and slots; by the naming convention, explicit where names differ | *The mapping* |
| **`dedal-figma pull`** | the CLI: fetches a frame from the Figma REST API, converts it, validates it, writes the templates and downloads the images | *dedal-figma pull* |
| **`dedal-figma audit` / `component`** | the library next to the contract: which components match, drifted or are missing in the code; a proposed contract entry for a component, with the questions to ask | *dedal-figma pull* |
| **`dedal-mcp`** | an MCP server: the same pull, validation and the contract as JSON Schema, for agents | *Agents: dedal-mcp and the skill* |
| **`figma-to-dedal`** | a Claude Code skill: pulls a frame, sorts the report into fixes, saves the template | *Agents: dedal-mcp and the skill* |
| **`dedal-figma build`** + the Dedal plugin | the other direction: a template → a frame in the Figma file, from its library components (`figma-plugin/`, run in Figma desktop) | *dedal-figma pull* |
| **`page-to-dedal`** | a Claude Code skill: a description of a page → a template from the existing components (and a Figma frame), asking where the description is open | *Agents: dedal-mcp and the skill* |
| **`figma-component-to-code`** | a Claude Code skill: a Figma component → a contract entry and a registry component, asking where the design is open | *Agents: dedal-mcp and the skill* |
| **`examples/figma`** | a landing page designed in Figma, pulled and rendered by Dedal | *A page from Figma, end to end* |

How to build the Figma file so that it converts cleanly — sections as components, content in slots, images — is in *Preparing a Figma file*, written for designers.

## What maps to what

| In Figma | In the template |
|---|---|
| an instance of a library component (or a variant of a component set) | a block — the component's name is the contract name (`Button` → `button`, `SectionHeading` → `sectionHeading`) |
| component properties: text, variant, boolean, instance swap | props — `Label#3:0` → `label`, `variant` → `variant`; an instance swap gives the swapped component's name |
| a native slot (a `SLOT` property) | a slot of the same name (`'one'` or `'many'`, from the contract); any other slot → `children` |
| an image fill (with `image()` in the mapping) | a prop with the image's path, after the pull downloads it |
| a frame or a group | layout — its content takes its place; a frame becomes a block only through `frame()` |
| a text layer outside any component | reported — or, with the `text` option, a text block with the name of its Figma text style (`h2`, `body`) |
| a hidden layer | skipped |

Spacing, sizes and colors stay in the components and the design tokens; a template carries structure and props, not pixels. Texts typed in Figma become props — for a heading that's the content, for a card that will get data it's a placeholder the data replaces.

## From Figma to the page

1. **Design** — designers build the page frame from the library's components (*Preparing a Figma file*).
2. **Pull** — `dedal-figma pull` (or an agent through `dedal-mcp`, or a job triggered by a Figma webhook) converts the frame and checks it against the contract. A template that doesn't match isn't written; everything left out is listed.
3. **Store** — the template is saved as a draft in your template store; previewed, published with a new version (*Templates from a page builder, CMS or database*). In the example it's simply a file in the repository.
4. **Render** — the frontend renders it with its registry; the page follows the frame.

The split between the teams: designers change pages freely within the design system; a new component, prop or variant is a change to the contract and the registry — code, reviewed and released first. A design that uses something the code doesn't have stops at step 2, with the layer named.

## What to watch out for

- **Names are the contract.** Renaming a component, a property or a slot in Figma without renaming it in the contract fails the pull — on purpose. Agree on the names with the design team, like any API.
- **One contract per component library.** A design built on library A is converted with A's contract and rendered with A's registry; there's no translation between libraries.
- **`ok: true` means valid, not faithful.** The template matches the contract; whether it matches the design is what `unmapped` and `warnings` tell you — read them.
- **Not yet:** the Dedal plugin as a *source* — it builds frames from templates; pulling a selected frame without a token is planned — pulling only the changed sections, Figma's variables (design tokens) in templates.
